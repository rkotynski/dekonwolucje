# Python API

The numerical algorithms and all PSF generators used by the GUI are available without PyQt5 through `deconv.api`. The API accepts either the native `GrayImage` and `PSF` objects or two-dimensional NumPy arrays.

## Installation

```bash
python -m pip install -e .
```

Optional Torch/CUDA algorithms require PyTorch:

```bash
python -m pip install -e "[gpu]"
```

## Coverage

`available_algorithms()` returns all 15 registered methods:

- Wiener
- Richardson-Lucy
- Richardson-Lucy-Wiener
- Blind Richardson-Lucy
- Landweber
- Landweber Wiener-preconditioned
- Block Kaczmarz
- Richardson-Lucy-Rosen
- Torch batch Wiener
- Torch batch Richardson-Lucy
- Torch batch Richardson-Lucy-Wiener
- Torch batch Richardson-Lucy-Rosen
- Torch batch Landweber
- PyTorch Adam TV-MAP
- PyTorch Blind Adam TV-MAP

Every method can be called through `run_deconvolution()`. Convenience wrappers are provided for every registered method.

`available_psf_generators()` returns all PSF families generated by the GUI:

- `gaussian`
- `motion` (horizontal or oblique according to `angle_deg`)
- `high_frequency`
- `lens_incoherent`

## Main objects

- `GrayImage`: image values in `image.data`.
- `PSF`: non-negative unit-sum kernel in `psf.kernel`.
- `DeconvolutionResult`: final `image`, recorded `history`, `metrics`, and textual `info`.

Blind methods additionally store the estimated PSF in the result metadata.

## Image and PSF generation

```python
from deconv.api import (
    generate_test_image,
    generate_gaussian_psf,
    generate_motion_psf,
    generate_high_frequency_psf,
    generate_lens_incoherent_psf,
    generate_psf,
)

image = generate_test_image(width=384, height=256)
gaussian = generate_gaussian_psf(size=21, sigma=3.0)
motion = generate_motion_psf(size=31, angle_deg=35.0)
hf = generate_high_frequency_psf(size=31, frequency=5.0, sigma=4.0)
lens = generate_lens_incoherent_psf(
    size=65,
    focal_length=0.05,
    distance_before=0.10,
    distance_after=0.10,
    wavelength=550e-9,
    aperture_diameter=0.005,
)

# Equivalent dispatcher form:
motion_2 = generate_psf("motion", size=31, angle_deg=35.0)
```

## Forward disturbance model

```python
from deconv.api import disturb_image

disturbed = disturb_image(
    image,
    motion,
    noise_sigma=0.01,
    noise_type="Gaussian",
    seed=7,
)
```

The forward model is the same zero-boundary linear `same` convolution as in the GUI. `seed` makes synthetic noise reproducible.

## General algorithm execution

```python
from deconv.api import run_deconvolution

result = run_deconvolution(
    disturbed,
    motion,
    algorithm="Richardson-Lucy",
    iterations=40,
    epsilon=1e-8,
    non_negative=True,
)
restored = result.image.data
history = [frame.data for frame in result.history]
```

Use `default_parameters(name)` to inspect all accepted settings and `available_algorithms()` to obtain canonical names. A `params` mapping may be supplied; keyword arguments override that mapping.

## Automatic parameter selection (`Auto`)

The GUI-independent API exposes the same conservative parameter-selection rules as the GUI:

```python
from deconv.api import AutoTuneOptions, auto_deconvolve

tuning = auto_deconvolve(
    disturbed,
    motion,
    algorithm="Richardson-Lucy",
    reference=image,  # optional independent ground truth
    params={
        "iterations": 20,
        "epsilon": 1e-8,
        "begin_with_wiener": False,
    },
    auto_options=AutoTuneOptions(
        strategy="quadratic",
        use_torch_equivalent=True,
        tune_boolean=False,
        tune_categorical=False,
    ),
    progress_callback=print,
)

print(tuning.best_params)
restored = tuning.deconvolution_result.image.data
```

`auto_tune_parameters()` only selects parameters unless `run_best=True`; `auto_deconvolve()` always performs the accepted final reconstruction. Both return an `AutoTuningResult` containing the initial and accepted parameters, scores, number of evaluated candidates, elapsed time, status text, and optional final `DeconvolutionResult`.

With an independent `reference`, Auto maximizes the best PSNR found in the stored iteration history. Without a reference, plain Wiener uses generalized cross-validation (GCV); the other algorithms use the same no-reference criterion as the GUI, combining reblur consistency, normalized total variation, intensity preservation, and residual whiteness.

Available strategies are returned by `available_auto_strategies()`:

- `quadratic`: fast coordinate search with a local parabolic refinement for numeric parameters;
- `full_batched`: a bounded local Cartesian search, evaluated in batches when the selected implementation supports batched Auto.

The Auto options independently control numeric, Boolean, categorical, denoiser, TV, and Wiener-initialization tuning. Optional processing stages that are disabled in the initial parameters remain frozen, including their hidden dependent values. A plain algorithm may be tuned through its Torch-batched equivalent and then validated on the requested implementation. Set `use_torch_equivalent=False` for strict single-implementation tuning.

An optional `progress_callback` receives status messages. An optional `stop_event` with an `is_set()` method requests cooperative cancellation between candidate evaluations; unlike the GUI watchdog, the public synchronous API does not terminate the caller process during a long individual numerical iteration.

The complete example is `examples/auto_richardson_lucy_motion.py`.

## Boundary models and PSF preparation

The API uses the same calculation-safe PSF preparation as the GUI. The PSF is non-negative and normalized to unit sum. The Wiener methods use circular FFT convolution; most iterative methods use zero-boundary linear convolution and its exact adjoint. Border behavior can therefore differ even for the same image and PSF.

## Advanced progress and stopping hooks

Iterative algorithms accept `_iteration_callback` and `_stop_event`. The callback receives `(current, total)` and a set event requests cooperative stopping after the current iteration. These underscored hooks are advanced and less stable than the main API.
